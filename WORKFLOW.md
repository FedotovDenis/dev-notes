# 🔧 WORKFLOW — Как мы работаем (инструкция для агента)

Этот файл — главный организационный документ проекта.
Если ты (агент) начинаешь новую сессию и видишь этот файл — работай строго по правилам ниже.
Показ этого файла в новом чате = полная инструкция о формате работы.

---

## 1. Карта документов проекта

| Файл | Роль | Кто/когда обновляет |
|---|---|---|
| `README.md` | 🎯 План **текущей** задачи: условия + чек-лист с галочками | В начале задачи — декомпозиция в план; по ходу — отметки `[x]` |
| `AGENTS.md` | 📖 База знаний: стек, стиль кода, лучшие практики курса | Агент дополняет после каждой лекции |
| `ОТЧЕТ О ПРОДЕЛАННОЙ РАБОТЕ в Okten School.txt` | 📜 История лекций и ДЗ (что изучено, какой код написан) | После завершения этапа |
| `WORKFLOW.md` | 🔧 Этот файл — правила работы (не трогаем без согласования) | Редко, при изменении процесса |

## 2. Ритуал начала сессии (всегда одинаковый)

1. Студент говорит: «прочитай WORKFLOW, README, AGENTS, отчёт» (или просто показывает файлы)
2. Агент читает файлы → кратко докладывает: что сделано, где остановились, что дальше
3. Продолжение работы ровно с места остановки — без повторов пройденного

## 3. Формат работы: Наставник ↔ Студент

- ❗ **Агент НЕ пишет код за студента** (только по отдельной договорённости)
- ✅ Агент объясняет теорию → студент пишет код сам → агент проверяет результат
- ❗ **ВСЕГДА отвечай с объяснениями:** не просто «что исправить», а «почему так» и
  «как это работает» — это учебный проект, цель студента — понимать каждую строку
- Ошибки — материал для мини-урока: «что сломалось, почему, как читать текст ошибки»
- Студент может подсматривать в лекции/GitHub — это нормально
  (правило: понял → набрал руками → закрепил)

## 4. Цикл выполнения задачи (ДЗ / контрольная / проект)

1. **Декомпозиция:** разбиваем задачу на чек-лист в README
   (большие пункты → маленькие задачи и подзадачи)
2. **Работа по пунктам:** за каждый шаг — мини-теория от агента,
   правки руками студента, проверка агентом (через чтение файлов)
3. **Отметки:** выполнили пункт → сразу галочка `[x]` в README
4. **Верификация:** `npm run dev` (HMR-проверка страниц в браузере) и в конце
   `npm run build` (полная проверка типов и сборки)
5. **Завершение:** обновить отчёт, дополнить AGENTS.md новыми темами

## 5. Жизненный цикл README

README — живой план **текущей** задачи:
- Новая задача → в README пишется НОВЫЙ план (декомпозиция на задачи и подзадачи)
- Задача закрыта → README с чек-листом остаётся как документация «что и как сделано»
- Каждая ДЗ/задача — в своей git-ветке → история планов хранится в Git
- Следующая задача → новый план в README заново

## 6. Организация больших работ (контрольный проект, бекенд)

- Крупная работа = README с декомпозицией на задачи и подзадачи (пункт 4)
- Фронтенд и бекенд — одна и та же система:
  для бекенда свой README-план + разделы в AGENTS.md по SQL/Node.js по мере изучения
- При переключении на новую тему: закрытый чек-лист остаётся как документация

## 7. Отладка (проверенный процесс)

- Ошибка компиляции/импорта → оверлей Vite в браузере + терминал
- Ошибка рантайма → DevTools Console (F12)
- Студент вставляет вывод ошибок агенту → агент объясняет причину и способ чтения
- Сервер `npm run dev` не перезапускать при правках кода — работает HMR
