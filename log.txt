## 📜 Отчет по лекции: lessons/lesson1/component

__Дата:__ 5 июля 2026 г.

__Тема:__ Основы компонента React и передача props.

__Краткое описание:__ Данная лекция демонстрирует создание простого функционального компонента в React с использованием TypeScript, а также принцип передачи данных в компонент через props. Она является вводной и показывает базовую структуру React-приложения, состоящего из корневого компонента `App` и переиспользуемого компонента `MyComponent`.

__Основные изменения/функциональность:__

- Создан файл `src/components/MyComponent.tsx`, содержащий функциональный React-компонент `MyComponent`.

- Компонент `MyComponent` принимает один `prop` под названием `text` типа `string` и отображает его внутри `div`.

  ```typescript
  // src/components/MyComponent.tsx
  type MyComponentPropType = {text: string}

  const MyComponent: FC<MyComponentPropType> = ({text}) => {
      return (
          <div>
              {text}
          </div>
      );
  };
  ```

- В `src/App.tsx` компонент `MyComponent` импортируется и используется трижды, каждый раз с разным значением `prop` `text` (`"Hello 1"`, `"Hello 2"`, `"Hello 3"`).

  ```typescript
  // src/App.tsx
  import MyComponent from "./components/MyComponent.tsx";

  function App() {
    return (
      <>
          < MyComponent text={'Hello 1'} />
          < MyComponent text={'Hello 2'} />
          < MyComponent text={'Hello 3'} />
      </>
    )
  }
  ```

__Изученные концепции/технологии:__

- __Функциональные компоненты React:__ Базовый способ создания компонентов в React.
- __Props (свойства):__ Механизм передачи данных от родительского компонента к дочернему.
- __TypeScript в React:__ Использование `type` для определения типов `props` (`MyComponentPropType`) и `FC` (Functional Component) из React для явного указания типа компонента.
- __Импорт/Экспорт модулей:__ Стандартный синтаксис ES-модулей для организации кода.
- __JSX:__ Синтаксис для описания пользовательского интерфейса.

__Нюансы/Лучшие практики:__

- Четкое определение типов для `props` с помощью TypeScript улучшает читаемость кода и предотвращает ошибки во время разработки.
- Разделение приложения на мелкие, переиспользуемые компоненты (`MyComponent`) является ключевым принципом React для поддержания чистоты кода и удобства разработки.
- Использование `FC` из `"react"` явно указывает, что `MyComponent` является функциональным компонентом, что может быть полезно для ясности, хотя в современных версиях TypeScript это часто выводится автоматически.

__Вопросы/Дальнейшие шаги:__

- Далее мы должны перейти к анализу домашнего задания, соответствующего этой лекции, начиная с ветки `hw/hw1/task1`.





## 📜 Отчет по домашнему заданию: hw/hw1/task1

__Дата:__ 5 июля 2026 г.

__Тема:__ Работа с массивами и метод `map()` в React.

__Краткое описание:__ В этом домашнем задании нужно было создать массив строк с названиями курсов и отобразить их в виде списка на странице, используя метод `map()`. Это первое знакомство с рендерингом списков в React.

__Основные изменения/функциональность:__

- В `src/App.tsx` создан массив `coursesTitleArray` с названиями курсов Okten School.
- Компонент `App` переписан со стрелочной функции (`const App = () => {...}`) вместо обычной функции.
- Вместо использования `MyComponent` теперь используется метод `map()` для динамического рендеринга элементов списка `<li>`.
- Добавлены стили для `<li>` в `src/App.css`.

__Код:__

```typescript
// src/App.tsx
import './App.css'

const coursesTitleArray: string[] = [
    'JavaScript Complex',
    'Java Complex',
    'Python Complex',
    'QA Complex',
    'Fullstack',
    'Frontend'
];

const App = () => {
  return (
    <>
        <ul>
            {
                coursesTitleArray.map((value, index) => <li key={index}>{value}</li>)
            }
        </ul>
    </>
  )
}

export default App
```

```css
/* src/App.css */
li {
  background: lightcyan;
  list-style: none;
  padding: 10px;
  margin: 10px;
  border-radius: 5px;
}
```

__Изученные концепции/технологии:__

- __Метод `map()` в JSX:__ Использование `map()` для трансформации массива данных в массив JSX-элементов.
- __Стрелочные функции для компонентов:__ Компонент `App` переписан как стрелочная функция (`const App = () => {...}`).
- __Атрибут `key`:__ Каждому элементу списка присваивается уникальный `key` (в данном случае `index`), что необходимо React для эффективного обновления DOM.
- __Типизация массива:__ Использование `string[]` для явного указания типа массива строк.
- __CSS-стилизация:__ Базовые стили для элементов списка (фон, отступы, скругление).

__Нюансы/Лучшие практики:__

- Использование `index` в качестве `key` — это распространенная практика для статических списков, но для динамических списков (с добавлением/удалением элементов) лучше использовать уникальные идентификаторы.
- Стрелочная функция с неявным возвратом (`<li key={index}>{value}</li>`) делает код более лаконичным.
- Массив данных вынесен за пределы компонента, что является хорошей практикой для статических данных.

## 📜 Отчет по лекции: lessons/lesson2/useState-hook

__Дата:__ 8 июля 2026 г.

__Тема:__ Хук состояния `useState`, обработка событий `onClick`, счетчик.

__Краткое описание:__ Первое знакомство с хуком `useState` в React. Создан простой счетчик с двумя кнопками: increment (увеличение) и decrement (уменьшение). Значение счетчика отображается в теге `<h1>`.

__Основные изменения/функциональность:__

- Импортирован хук `useState` из React.
- Создана переменная состояния `counter` и функция для ее обновления `setCounter` с начальным значением `0`.
- Две кнопки: `increment` (увеличивает счетчик) и `decrement` (уменьшает счетчик).
- Значение счетчика отображается в `<h1>{counter}</h1>`.

__Код:__

```typescript
// src/App.tsx
import './App.css'
import {useState} from "react";

const App = () => {

    let [counter, setCounter] = useState(0);

  return (
    <div>
        <h1>{counter}</h1>

        <button onClick={() => {
            setCounter(++counter)
        }}>increment</button>

        <button onClick={() => {
            setCounter(counter--)
        }}>decrement</button>
    </div>
  )
}

export default App
```

__Изученные концепции/технологии:__

- __useState:__ Базовый хук React для добавления состояния в функциональный компонент. Возвращает массив из двух элементов: текущее значение и функцию для его обновления.
- __Деструктуризация массива:__ `let [counter, setCounter] = useState(0)` — синтаксис деструктуризации для получения значения и функции-сеттера.
- __onClick:__ Обработчик клика по кнопке в React. Принимает стрелочную функцию.
- __Рендеринг переменной в JSX:__ `{counter}` — отображение значения JavaScript-переменной внутри JSX.

__Нюансы/Лучшие практики:__

- ⚠️ __ВАЖНО (антипаттерн):__ В коде используется мутация состояния через `++counter` и `counter--`. Это __неправильный подход__ в React. Состояние нельзя мутировать напрямую. Правильно использовать:

  ```typescript
  // Правильный вариант 1:
  setCounter(prev => prev + 1)

  // Правильный вариант 2:
  setCounter(counter + 1)
  ```

  Использование `++counter` изменяет переменную `counter` напрямую, что может привести к непредсказуемому поведению и багам, особенно при асинхронных операциях.

- Использование `let` вместо `const` для деструктуризации `useState` — тоже не лучшая практика. `const [counter, setCounter] = useState(0)` — предпочтительный вариант, так как мы не переназначаем переменную.

## 📜 Отчет по лекции: lessons/lesson3_2/router-demo

__Дата:__ 10 июля 2026 г.

__Тема:__ Вынос роутинга в отдельный модуль, создание архитектурной структуры (маршруты, сервисы, константы), типизация, компонент навигационного меню.

__Краткое описание:__ Эта лекция демонстрирует, как масштабировать и правильно структурировать приложение с роутингом. Вместо того чтобы хранить настройки роутинга в `main.tsx` или `App.tsx`, они выносятся в отдельный файл `src/router/routes.tsx`. Вводятся папки `src/constans` (для URL-адресов) и `src/services` (сервисный слой API), а также типизированные модели пользователей в `src/model/`. В меню навигации используется компонент `Link`.

__Основные изменения/функциональность:__

- __Новая структура папок:__

  - `src/router/` — конфигурация маршрутизатора.
  - `src/constans/` — константы (включая API URL-адреса).
  - `src/services/` — слой работы с сетью (fetch-запросы).
  - `src/model/` — TypeScript интерфейсы моделей.

- __Вынос роутера:__ Вся конфигурация маршрутов перенесена в `src/router/routes.tsx`. В `src/main.tsx` импортируется готовый объект `routes` и передается в `<RouterProvider/>`.

- __Слой сервисов:__ Создан `src/services/api.service.ts` с объектом `userService`, содержащим асинхронный метод `getUsers()`, типизированный через `Promise<IUser[]>`.

- __Константы путей:__ В `src/constans/urls.ts` вынесен базовый URL `https://jsonplaceholder.typicode.com` и эндпоинты.

- __Типизированный рендеринг списка пользователей:__ `UsersPages` рендерит `UsersComponent`, который через хук `useEffect` обращается к `userService.getUsers()`, сохраняет пользователей в `state` и мапит их в дочерние компоненты `UserComponent`, отображая `username`.

// src/components/users/UsersComponent.tsx — Компонент списка пользователей с пагинацией
import { useSearchParams } from "react-router-dom"
import { useEffect, useState } from "react"
import type { IUser } from "../../models/IUser"
import { apiService } from "../../services/api.service"
 
export const UsersComponent = () => {
    const [query] = useSearchParams()
    const [users, setUsers] = useState<IUser[]>([])
    const [loading, setLoading] = useState(false)
 
    useEffect(() => {

        setLoading(true)

            .catch(err => {

            })

                <p>Loading...</p>
            ) : (
                <ul>
                    {users.map(user => (
                        <li key={user.id}>{user.firstName} {user.lastName}</li>
                    ))}
                </ul>
            )}
            {!loading && users.length === 0 && <p>No users found.</p>}
        </div>
    )
}

export const apiService = {

Тема: Контролируемые компоненты (Controlled Components) в React, управление состоянием форм.

Краткое описание: Лекция демонстрирует работу с контролируемыми компонентами в React. В отличие от неконтролируемых компонентов (lesson5), контролируемые компоненты полностью управляются React через state. Значения полей формы привязаны к состоянию компонента через проп value, а изменения отслеживаются через обработчик onChange. type IFormProps = {
    username: string;
    password: string;

export const userValidator = Joi.object({

        'string.pattern.base': 'Wrong username'

    age: Joi.number().min(1).max(120).required().messages({

    })
})

// src/validators/CarValidators.ts — Joi схема валидации
import * as joi from 'joi'
 
export const CarValidators = joi.object({
    brand: joi.string().min(1).max(20).required().messages({
        'string.empty': 'Brand is required',
        'string.min': 'Brand must be at least 1 character',
        'string.max': 'Brand must be at most 20 characters'
    }),
    model: joi.string().min(1).max(20).required().messages({
        'string.empty': 'Model is required',
        'string.min': 'Model must be at least 1 character',
        'string.max': 'Model must be at most 20 characters'
    }),
    year: joi.number().min(1990).max(new Date().getFullYear()).required().messages({
        'number.base': 'Year must be a number',
        'number.min': 'Year must be at least 1990',
        'number.max': 'Year must be at most ' + new Date().getFullYear()
    }),
    price: joi.number().min(0).required().messages({
        'number.base': 'Price must be a number',
        'number.min': 'Price cannot be negative'
    }),
})

import type { ICar } from "../../models/ICar";

Тема: Аутентификация в React, JWT токены, refresh токены, localStorage, axios интерсепторы, кастомные хуки.

Краткое описание: Лекция демонстрирует реализацию аутентификации в React приложении с использованием JWT токенов. Реализованы функции login (получение access и refresh токенов), refresh (обновление токенов), и загрузка защищенных ресурсов. Токены хранятся в localStorage. Axios интерсептор автоматически добавляет Authorization заголовок для GET запросов. Создан кастомный хук useAuthRefresh для обновления токенов. Используется API dummyjson.com для аутентификации и получения продуктов.

_Основные изменения/функциональность:

В api.services.ts создан axios инстанс с baseURL: "https://dummyjson.com/auth".
Реализована функция login для получения токенов (accessToken, refreshToken) и сохранения в localStorage.
Реализована функция refresh для обновления токенов через refresh токен.
Реализована функция loadAuthProducts для загрузки защищенных ресурсов (требует авторизации).
Request interceptor добавляет Authorization заголовок с accessToken для всех GET запросов.
В helpers.ts создана функция retrieveLocalStorage для типизированного получения данных из localStorage.
В useAuthRefresh.ts создан кастомный хук для обновления токенов с состоянием loading и error.
В models созданы интерфейсы: IUserWithTokens, ITokenPair, IProduct, IProductsResponseModelsType.
В login реализована форма логина с использованием FormData.
В auth-resources реализован компонент для загрузки и отображения защищенных продуктов с автоматическим refresh токенов.

// src/services/api.services.ts — API сервис с аутентификацией
import axios from "axios";
import type { IUserWithTokens } from "../models/IUserWithTokens";
import type { IProduct } from "../models/IProduct";
import type { IProductsResponseModelsType } from "../models/IProductsResponseModelsType";
import { retrieveLocalStorage } from "./helpers";
import type { ITokenPair } from "../models/ITokenPair";
 
type LoginData = {
  username: string;
  password: string;
  expiresInMins: number;
};
 
const axiosInstance = axios.create({
  baseURL: "https://dummyjson.com/auth",
  headers: {
    "Content-Type": "application/json",
  },
});
 
axiosInstance.interceptors.request.use((requestObject) => {
    if(requestObject.method?.toUpperCase() === "GET") {
       requestObject.headers.Authorization = 'Bearer ' + retrieveLocalStorage<IUserWithTokens>("user").accessToken;
    }
    return requestObject;
})
 
export const login = async ({username,password, expiresInMins,}: LoginData): Promise<IUserWithTokens> => {
  const { data: userWithTokens } = await axiosInstance.post<IUserWithTokens>("/login",{ username, password, expiresInMins });
  console.log("userWithTokens", userWithTokens);
  localStorage.setItem("user", JSON.stringify(userWithTokens));
  return userWithTokens;
};
 
export const loadAuthProducts = async (): Promise<IProduct[]> => {
  const { data } = await axiosInstance.get<IProductsResponseModelsType>("https://dummyjson.com/products");
  console.log(data.products);
  return data.products;
};
 
export const refresh = async () => {
  const iUserWithTokens = retrieveLocalStorage<IUserWithTokens>("user");
  const { data: {accessToken, refreshToken} } = await axiosInstance.post<ITokenPair>("/refresh", {
    refreshToken: iUserWithTokens.refreshToken,
    expiresInMins: 5,
  });
  iUserWithTokens.accessToken = accessToken;
  iUserWithTokens.refreshToken = refreshToken;
  localStorage.setItem("user", JSON.stringify(iUserWithTokens));
  return iUserWithTokens;
};

// src/services/helpers.ts — Хелпер для localStorage
export const retrieveLocalStorage = < T >(key: string) => {
const object = localStorage.getItem(key) || '';
if(!object){
    return {} as T;
}
const parse = JSON.parse(object);
return parse as T;
}

// src/hooks/useAuthRefresh.ts — Кастомный хук для refresh токенов
import { useState } from "react";
import { refresh } from "../services/api.services";
import type { IUserWithTokens } from "../models/IUserWithTokens";
 
export const useAuthRefresh = () => {
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
 
  const handleRefresh = async (): Promise<IUserWithTokens | null> => {
    setIsLoading(true);
    setError(null);
 
    try {
      const result = await refresh();
      return result;
    } catch (err) {
      const errorMessage =
        err instanceof Error ? err.message : "Refresh failed";
      setError(errorMessage);
      return null;
    } finally {
      setIsLoading(false);
    }
  };
 
  return { handleRefresh, isLoading, error };
};

type PropsType = {
  onLogin: (username: string, password: string) => void;
};
 
export const LoginFormComponent: FC<PropsType> = ({ onLogin }) => {
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {

📜 Отчет по лекции: lessons/lessons7-1/memo
Дата: 12 июля 2026 г.

Тема: React.memo для оптимизации ререндеров компонентов.

Краткое описание: Лекция демонстрирует использование React.memo для оптимизации производительности компонентов. memo - это HOC (Higher-Order Component), который запоминает результат рендеринга компонента и предотвращает его ререндер, если пропсы не изменились. В примере UserComponent обернут в memo, что предотвращает его ререндер при обновлении родительского UsersComponent. Для демонстрации добавлены console.log в оба компонента.

_Основные изменения/функциональность:

В UserComponent.tsx компонент обернут в memo().
В UsersComponent загружаются пользователи через fetch из jsonplaceholder.
В оба компонента добавлены console.log для отслеживания ререндеров.
При обновлении UsersComponent (например, при изменении state users) UserComponent не ререндерится благодаря memo.

_Изученные концепции/технологии:

React.memo: HOC для мемоизации компонентов и предотвращения лишних ререндеров.
Мемоизация: Запоминание результата рендеринга для переиспользования.
Оптимизация производительности: Использование memo для компонентов с тяжелым рендерингом.
Поверхностное сравнение пропсов: memo использует поверхностное сравнение (shallow comparison) пропсов по умолчанию.
_Нюансы/Лучшие практики:

Когда использовать memo: Для компонентов, которые часто ререндерятся без изменения пропсов, или имеют тяжелый рендеринг.
Когда НЕ использовать memo: Для простых компонентов с быстрым рендерингом (накладные расходы memo могут превысить выгоду).

Когда использовать useCallback: Для функций, которые передаются как пропсы в мемоизированные компоненты или используются в зависимостях других хуков.
Зависимости: Важно правильно указывать зависимости в массиве зависимостей для корректной работы мемоизации.
Не мемоизировать всё подряд: Мемоизация имеет накладные расходы. Использовать только там, где это действительно нужно.
useCallback для пропсов: Особенно полезен при передаче функций в компоненты обернутые в memo для предотвращения их ререндера.__

  error: Error | null;
}
 
export const useFetch = <T,>(url: string): UseFetchResult<T> => {
  const [data, setData] = useState<T>();
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);
 
  useEffect(() => {
    const controller = new AbortController();
 
    setIsLoading(true);
    setError(null);
 
    fetch(url, { signal: controller.signal })
      .then((response) => {
        if (!response.ok) {
          throw new Error(`HTTP ошибка: ${response.status}`);
        }
        return response.json();
      })
      .then((value) => {
        setData(value);
      })
      .catch((err) => {
        if (err.name !== 'AbortError') {
          setError(err);
        }
      })
      .finally(() => {
        setIsLoading(false);
      });
 
    return () => {
      controller.abort();
    };
  }, [url]);
 
  return { data, isLoading, error };
}

// src/redax/slices/userSlice/userSlice.tsx — Slice с async thunk
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';
import type { PayloadAction } from '@reduxjs/toolkit';
import type { IUser } from '../../../model/IUser.ts';
 
type UserSliceType = {
    users: IUser[]
}
 
const initialState: UserSliceType = {
    users: []
}
 
export const loadUsers = createAsyncThunk(
    'userSlice/loadUsers',
    async (_, thunkAPI) => {
        try {
            const users = await fetch('https://jsonplaceholder.typicode.com/users')
                .then(value => value.json())
            return thunkAPI.fulfillWithValue(users)
        } catch (e) {
            return thunkAPI.rejectWithValue('error')
        }
    }
)
 
const userSlice = createSlice({
    name: 'userSlice',
    initialState: initialState,
    reducers: {},
    extraReducers: builder => {
        builder
            .addCase(loadUsers.fulfilled, (state, action: PayloadAction<IUser[]>) => {
                state.users = action.payload
            })
            .addCase(loadUsers.rejected, (state, action) => {
                console.log(state)
                console.log(action)
            })
    }
})
 
export const userSlicsActions = {
    ...userSlice.actions,
    loadUsers
}
 
export default userSlice

// src/redax/slices/userSlice/userSlice.tsx — Расширенный slice с матчерами
import { createSlice, createAsyncThunk, isFulfilled, isRejected } from '@reduxjs/toolkit';
import type { PayloadAction } from '@reduxjs/toolkit';
import type { IUser } from '../../../model/IUser.ts';
 
type UserSliceType = {
    users: IUser[],
    user: IUser | null,
    loadState: boolean
}
 
const initialState: UserSliceType = {
    users: [],
    user: null,
    loadState: false
}
 
export const loadUsers = createAsyncThunk(
    'userSlice/loadUsers',
    async (_, thunkAPI) => {
        try {
            const users = await fetch('https://jsonplaceholder.typicode.com/users')
                .then(value => value.json())
            return thunkAPI.fulfillWithValue(users)
        } catch {
            return thunkAPI.rejectWithValue('error')
        }
    }
)
 
export const loadUser = createAsyncThunk(
    'userSlice/loadUser',
    async (id: string, thunkAPI) => {
        try {
            const user = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`)
                .then(value => value.json())
            return thunkAPI.fulfillWithValue(user)
        } catch {
            return thunkAPI.rejectWithValue('error')
        }
    }
)
 
const userSlice = createSlice({
    name: 'userSlice',
    initialState: initialState,
    reducers: {
        changeLoadState(state, action: PayloadAction<boolean>) {
            state.loadState = action.payload
        }
    },
    extraReducers: builder => {
        builder
            .addCase(loadUsers.fulfilled, (state, action: PayloadAction<IUser[]>) => {
                state.users = action.payload
            })
            .addCase(loadUsers.rejected, (state, action) => {
                console.log(state)
                console.log(action)
            })
            .addCase(loadUser.fulfilled, (state, action: PayloadAction<IUser>) => {
                state.user = action.payload
            })
 
            .addMatcher(isFulfilled(loadUsers, loadUser), (state) => {
                state.loadState = true
            })
            .addMatcher(isRejected(loadUsers, loadUser), (state) => {
                console.log(state)
            })
    },
});
 
export const userSlicsActions = {
    ...userSlice.actions,
    loadUsers, 
    loadUser
}
 
export default userSlice

import { useEffect } from "react"

import { useAppSelector } from "../redax/hooks/useAppSelector.tsx"
import { userSlicsActions } from "../redax/slices/userSlice/userSlice.tsx"
import { useAppDispatch } from "../redax/hooks/useAppDispatch.tsx"
 
export const UsersPages = () => {
    const {users, loadState} = useAppSelector(state => state.userSlice)
    const dispatch = useAppDispatch()
 
    useEffect(() => {
        dispatch(userSlicsActions.loadUsers())
    }, [dispatch])

        <div>
            {!loadState && <div>Loading...</div>}
            {
                users.map((user) => {

                })
            }
        </div>
    )
}

// src/pages/UserPage.tsx — Страница отдельного пользователя
import { useEffect } from "react"
import { useAppSelector } from "../redax/hooks/useAppSelector.tsx"
import { userSlicsActions } from "../redax/slices/userSlice/userSlice.tsx"
import { useAppDispatch } from "../redax/hooks/useAppDispatch.tsx"
import { useParams } from "react-router-dom"
 
export const UserPage = () => {
    const {userId: id} = useParams()
    const {loadState} = useAppSelector(state => state.userSlice)
    const dispatch = useAppDispatch()
 
    useEffect(() => {
        if (id) {
            dispatch(userSlicsActions.loadUser(id))
        }
    }, [id])
 
    const user = useAppSelector(state => state.userSlice.user)
    return(
        <div>
            <h2>user {id}</h2>
            {!loadState && <div>Loading...</div>}
            {user && <div>{user.name}</div>}
        </div>
    )
}
