# Правила и архитектура проекта (Отчет по изученному материалу)

Здесь зафиксированы все ключевые подходы, архитектурные решения и особенности стека, которые мы используем в проекте, на основе изученных лекций и домашних заданий. Этот файл служит базой знаний и инструкцией.

## 1. Стек технологий
- **Фреймворк:** React 18+
- **Сборщик:** Vite
- **Язык:** TypeScript (строгая типизация)
- **Роутинг:** React Router DOM (v6, подход с `createBrowserRouter` и `RouterProvider`)

## 2. Структура проекта
- `/src/components/` — переиспользуемые и изолированные компоненты (например: `Menu`, `UsersComponent`, `UserComponent`).
- `/src/models/` — TypeScript-интерфейсы и типы (`IUser.ts`, `IPostsModel.ts` и т.д.).
- `/src/services/` — сервисы для работы с API (`api.service.ts`).
- `/src/layouts/` — компоненты-обертки с `Outlet` (например, `MainLayout.tsx`).
- `/src/pages/` — компоненты страниц маршрутизации.
- `/src/constants/` — константы, такие как URL-адреса для API.

## 3. Правила написания компонентов
- Использование **исключительно функциональных компонентов** (FC).
- Типизация пропсов через `type` или `interface` с использованием `FC<PropsType>`.
- Использование хуков:
  - `useState` — для управления локальным состоянием (например, данными, а также состоянием загрузки `loading`).
  - `useEffect` — для побочных эффектов (например, фетчинг данных при монтировании компонента или при изменении зависимостей, таких как query-параметры). При асинхронных запросах рекомендуется управлять состоянием загрузки и обрабатывать ошибки через `catch`. Для предотвращения утечек памяти и race conditions при размонтировании компонента следует использовать `AbortController` (отмена запросов `fetch`).
- Использование свойства `children` (тип `ReactNode`) для прокидывания вложенного контента в компоненты-контейнеры.
- Поднятие состояния (State Lifting) — передача callback-функций из родительского компонента в дочерний для обновления состояния родителя.

## 4. Работа с API и переменными окружения
- Запросы к API пишутся через `fetch` и асинхронные функции (`async/await` или промисы `.then()`).
- Базовые URL и токены хранятся в файле `.env` с префиксом `VITE_` (например, `VITE_API_BASE_URL`).
- Доступ к переменным окружения осуществляется через `import.meta.env`.

## 5. Маршрутизация (React Router v6)
- Настройка роутов через `createBrowserRouter`.
- Использование `<Outlet/>` для вложенных маршрутов внутри Layout-компонентов, а также для вложенных дочерних маршрутов (например, внутри страницы пользователей).
- Навигация между страницами осуществляется:
  - Декларативно — с помощью компонента `<Link to="...">`.
  - Императивно — с помощью хука `useNavigate()`.
- Передача данных между маршрутами (State Forwarding):
  - Через свойство `state` в `<Link>` (например, `<Link to="details" state={item}>`) или в параметрах `navigate('path', { state: data })`.
  - Получение переданных данных на целевой странице через хук `useLocation()` (например, `const { state } = useLocation(); const user = state as IUser;`).
- Динамическая маршрутизация:
  - Определение динамических параметров в пути (например, `path: 'posts/:userId'`).
  - Извлечение параметров пути внутри компонента с помощью хука `useParams()` (например, `const { userId } = useParams();`).
- Многоуровневая вложенность маршрутов:
  - Использование массива `children` внутри других `children` для построения сложной иерархии путей (например, `/users/jsonplaceholder` и `/users/dummyjson`).
- Query-параметры и Пагинация (Search Params):
  - Использование хука `useSearchParams` для работы с параметрами запроса в URL (например, `?page=2`).
  - Чтение параметра: `searchParams.get('page')`.
  - Обновление параметра: `setSearchParams({ page: '2' })`.
  - Пагинация часто реализуется как отдельный Layout (`PaginationLayout`), оборачивающий целевые страницы.


## 6. Рендеринг списков (List Rendering)
- Отрисовка массивов данных происходит с помощью метода `map()` (например, `users.map(user => <UserComponent item={user} key={user.id}/>)`).
- Обязательно использование уникального пропса `key` для каждого корневого элемента в возвращаемом из `map()` JSX.

## 7. Работа с формами и валидацией
- **Контролируемые формы**: использование `useState` и обработчика `onChange` для управления состоянием инпутов, но предпочтительнее использовать хук.
- **react-hook-form**:
  - Использование хука `useForm` (методы `register`, `handleSubmit`, состояние `formState: { errors, isValid }`).
  - Опция `{ mode: 'all' }` для проверки при всех изменениях.
- **Joi валидация**:
  - Создание схемы через `Joi.object({})` с цепочкой правил (например, `.min()`, `.pattern()`, `.required()`) и методом `.messages({})` для кастомных ошибок.
  - Рекомендуется выносить схемы валидации в отдельную папку (например, `/src/validators/`).
  - Интеграция схемы в форму через `resolver: joiResolver(схема)`.
  - Для числовых полей при регистрации (`register`) использовать опцию `{ valueAsNumber: true }` (например, `{...register('price', { valueAsNumber: true })}`).

## 8. Запросы через Axios (вместо Fetch)
- Создание инстанса `axios.create({ baseURL, headers })`.
- Использование интерцепторов (interceptors):
  - `axiosInstance.interceptors.request.use` (добавление токена в заголовок `Authorization: Bearer <token>`, логирование).
  - `axiosInstance.interceptors.response.use` (обработка успешных/неуспешных ответов, автоматический рефреш токенов при 401 ошибке).
- Асинхронные функции извлекают `data` (например: `const { data } = await axiosInstance.get<IModelType>('/path')`).
- Отправка данных (POST/PUT): `const { data } = await axiosInstance.post<IModelType>('/path', body)`.

## 9. Аутентификация и работа с токенами (JWT)
- **Хранение токенов**: Токены (`accessToken`, `refreshToken`) и данные пользователя обычно сохраняются в `localStorage` (с использованием `JSON.stringify` и `JSON.parse`). Рекомендуется создавать типизированные хелперы для работы с `localStorage`.
- **Передача токена**: Добавление `accessToken` к защищенным запросам реализуется через `axiosInstance.interceptors.request.use`.
- **Рефреш токенов**: Обновление токена по истечении времени действия (`expiresIn`). Может быть реализовано через отдельный хук (например, `useAuthRefresh`) или перехватчик ответов Axios (interceptors.response), который ловит ошибку 401 (Unauthorized) и делает запрос на `/refresh`.
- **Неконтролируемые формы (FormData)**: Для простых форм логина можно использовать стандартный объект `FormData` в обработчике `onSubmit` (например, `const formData = new FormData(e.currentTarget); const username = formData.get("username");`), избегая создания лишних стейтов.

## 10. Оптимизация производительности (Performance Optimization)
- **`React.memo`**: Используется для обертки функциональных компонентов для предотвращения их лишних перерисовок (re-renders), если их пропсы (props) не изменились.
- **`useCallback`**: Используется для мемоизации функций. Предотвращает пересоздание функции при каждом рендере компонента, что особенно важно при передаче callback-функций в мемоизированные дочерние компоненты (чтобы не нарушать работу `React.memo`).
- **`useMemo`**: Используется для мемоизации значений (например, массивов, объектов или результатов тяжелых вычислений). Позволяет избежать повторных вычислений и пересоздания ссылочных типов данных при каждом рендере, если зависимости не изменились.

## 11. Продвинутые хуки и паттерны (Advanced Hooks & Patterns)
- **Кастомные хуки (Custom Hooks)**: Позволяют выносить повторяющуюся логику с использованием других хуков (например, логику фетчинга данных: `useFetch`) в отдельные переиспользуемые функции. Рекомендуется размещать их в папке `/src/hooks/`.
- **Context API (`createContext`, `useContext`)**: Используется для проброса данных (глобального стейта) сквозь дерево компонентов, минуя промежуточные уровни (prop drilling). Включает создание контекста (`createContext`), обертку дерева провайдером (`Context.Provider`) и потребление контекста в дочерних компонентах через хук `useContext`. Часто применяется для управления темами оформления или авторизацией. Рекомендуется использовать в комбинации с `useMemo` и `useCallback` для предотвращения лишних рендеров потребителей контекста.

## 12. State Management (Redux Toolkit)
- **Установка и настройка**: Использование `@reduxjs/toolkit` и `react-redux`. Создание глобального хранилища через `configureStore`.
- **Слайсы (Slices)**: Использование `createSlice` для объединения состояния (`initialState`), редюсеров (`reducers`) и действий (`actions`).
- **Асинхронные экшены (Async Thunks)**: Использование `createAsyncThunk` для выполнения асинхронных операций (например, запросов к API) и автоматической генерации экшенов (`pending`, `fulfilled`, `rejected`).
- **extraReducers**: Обработка состояний асинхронных экшенов (thunk) внутри `createSlice` с помощью `builder.addCase(loadUsers.fulfilled, ...)`. Для группировки обработчиков нескольких экшенов (например, обработка статусов загрузки или ошибок) используются матчеры: `builder.addMatcher(isFulfilled(action1, action2), ...)` и `isRejected`.
- **Провайдер**: Обертка всего приложения (например, в `main.tsx`) в `<Provider store={store}>` для предоставления доступа к состоянию.
- **Хуки для работы со Store**:
  - `useSelector` (типизированный как `useAppSelector`): для извлечения данных из состояния (`state => state.sliceName`).
  - `useDispatch` (типизированный как `useAppDispatch` с `AppDispatch`): для отправки действий (`actions`) и вызова thunk-ов в хранилище (например, `dispatch(loadUsers())`).
- **Типизация**: Строгая типизация стейта (`RootState` или `ReturnType<typeof store.getState>`), `dispatch` (`AppDispatch` или `typeof store.dispatch`) и экшенов (`PayloadAction<T>`).
